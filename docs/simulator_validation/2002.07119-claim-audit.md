## Project application

**E closes a standing gap in this repository's own modelling.** The leaked-inert single-qubit gate
convention is shared bit-for-bit by the exact density-matrix leg and the SV-MC kernel
(`carrier/exact/qutrit_dm.py` states the sharing explicitly), which is why they cannot referee each
other on it. The source shows the convention is standard practice and declared as an assumption in
published work. That is enough to satisfy `docs/FAITHFULNESS_PROTOCOL.md` §4's requirement to
*declare* the simplification with a source. It is **not** enough to bound it: the source gives no
error bound for the assumption either, so the simplification remains declared-but-unbounded on both
sides.

**D materially weakens a project prediction that had not yet been measured.** The prediction was
that the transversal echo converts leakage-occupancy parity into detector signal, and that this
would be a distinguishing capability. Two separate problems:

1. Prior art. Leakage becoming visible in the surface-code defect record is established for d3
   Surface-17 by this source, and independently by arXiv:1905.12731 via hidden Markov models on the
   parity string. The observable is not novel.
2. Possible unobservability, which is the sharper objection. If leakage already drives the affected
   check's defect probability to ~0.5, that check's bit is already randomized. A further
   deterministic parity flip applied to an already-random bit is not distinguishable in the marginal.
   This is a project inference from the source's stated 0.5, not a source claim, and it has not been
   tested — but it must be answered before any measurement is designed, because it predicts a null.

**C bears on a convention this repository has not declared.** `carrier/record_fold.py` uses
`d[r] = s[r] XOR s[r-1]`, and `docs/METRICS.md` records that as the shared convention without
stating the premise it depends on. Inspection of the parsed Google `d3_at_q6_7/X` r10 circuit shows
each round resets the eight measured ancillas (the nine data qubits are never reset) and declares
`DETECTOR ... rec[-8] rec[-16]`, i.e. adjacent-round — so the repository's convention is correct for
its own data. The gap is documentary: the premise is satisfied by the parsed circuit and is not
declared anywhere in the fold module or the metrics ledger, so a reader cannot tell the convention
is data-conditioned rather than universal. This source is the contrast case that makes it visible.

**A and B remain open and are the only place a contribution could still sit**, narrowed to: the
action of a deterministic transversal layer on stabilizer support parity and on an odd-weight
logical. Five external repositories and six papers do not treat it. That is not a field-wide gap;
it is the current extent of the search.

## Competing evidence and kill conditions

- **Competing source already found**: arXiv:1905.12731 (Science Advances 5, eaay3050) detects
  leakage from the parity-outcome string alone with hidden Markov models, and uses Pauli-frame
  transformations for the qubit-error half. Retained at `docs/papers/1905.12731v1.pdf`, unread
  beyond the abstract.
- **Adjacent hardware approach**: arXiv:2607.17204 achieves heralded leakage detection at readout by
  driving the computational transition during dispersive readout. Different mechanism, same goal.
  Retained at `docs/papers/2607.17204v1.pdf`, unread beyond the abstract.
- **Kill condition, fired**: the project claim "the transversal echo converts leakage occupancy into
  detector signal, and this is a distinguishing capability" is withdrawn on row D.
- **Kill condition, live**: if the ~0.5 randomization argument holds under measurement, the narrowed
  parity claim predicts a null and should not be pursued as a capability. Deciding this requires
  reading Appendix D of this source and inspecting Fig. 3e, neither of which was possible here.
- **Would revive the narrowed claim**: a regime where an affected check is NOT driven to 0.5 —
  for instance a leaked site on a check whose other sites remain computational, where the echo's
  parity contribution is deterministic while the leakage contribution is not.
